Burp入门笔记

Proxy 基础抓包

这里打开Burp自带的浏览器，输入”http://example.com/“
在Burp的Proxy模块的HTTP history看到数据包（基础抓包）

数据包里可以看到的内容

数据包分为请求包（Request）和响应包（Response）

  1. 请求包（左边）：是我们发给服务器的数据
  • 请求行：请求方法 (GET/POST) + 访问路径 + 参数 + HTTP 版本
  • 请求头（Header）：Host、User-Agent、Content-Type 等一堆说明信息
  • 请求体（Body）：POST 表单参数才会有，请求头和请求体之间必须空一行，GET 请求一般没有请求体
  1. 响应包（右边）：服务器返回给我们的数据
  • 状态行：HTTP 版本 + 状态码（例如200 OK代表请求成功）
  • 响应头：服务器信息、内容类型、缓存信息等
  • 响应体：网页的 HTML 源码，就是页面真正展示的内容，可以切换 Render 标签直接预览网页效果

GET 转 POST 表单包：

  • 请求方法 GET → POST
  • 移除 URL 后面的所有参数
  • 在请求头末尾空一行，在空行后填写参数（请求体）
  • ⭐在Host: example.com这一行后面另起一行，增加请求头：Content-Type: application/x-www-form-urlencoded（告诉服务器这是表单格式数据）

注：右侧Response中识别响应：200 OK 代表请求成功，右侧 Render 可以预览网页，Raw 查看源码

Proxy 的 Intercept 拦截

  • 打开Proxy模块中的intercept,打开拦截总开关（intercept on）
  • 在Burp自带浏览器中访问example.com
  • 发现浏览器会转圈卡住，这是因为请求被拦住了

  • 这时切回Burp就可以看到被拦到的GET请求
  • 在拦截界面可以直接修改请求行（在GET / 后面尝试加上?id=666）
  • 之后点击Forward放行，在浏览器就可以看到界面访问

注：example.com本身不会识别我们加的？id=666 这个参数，它只是一个静态示例页面，不管你后面加什么参数，它都只会返回这一段固定提示文字：“该域名仅用于文档示例……”，所以页面样子没变，不是操作失误

  • 拦截到数据包之后，发给 Repeater 的方法：在请求内容区域右键 → Send to Repeater
    之后可以进行调试，反复测试

http协议介绍

http协议-请求协议(GET,POST)

GET（如同寄快递，把需求写在快递面单的外面，任何人都能看见。）

请求行：请求方式+资源路径+查询参数（?后面就是参数）：/brand/findAll?name=OPPO&status=1
👉关键点：GET把参数直接挂在URL（请求路径）的问号?后边，用&隔开多个参数。
协议版本：HTTP/1.1
注：GET的所有参数放在请求行里面，不会放到下面的消息体。
GET /brand/findAll?name=OPPO&status=1 HTTP/1.1
“?”就是一个信号：后面开始是参数了！
这里有两个参数：
name=OPPO
👉 参数名字：name，参数的值：OPPO。意思就是：“我要查名字叫OPPO的东西”。
status=1
👉 参数名字：status，值：1。意思：“只找状态等于1的内容”。

PSOT（如同寄快递，把需求写在纸条上，封进包裹里面。）

请求行：请求方式+资源路径：/brand（这里没有?和参数）
协议版本：HTTP/1.1
注：post不会把参数放到网址上。而是打包放在数据包底部的请求体进行传送，从请求行看不到传递的数据。

http协议-响应协议

响应行：协议+状态码（例：404）

CTF Web 入门：HTTP 传参，data 还是 json？

一句话核心

服务端怎么读，你就怎么发。

题目回顾

页面源码直接展示了一段 PHP 代码：

判断方法

服务端读法 你怎么发
$_POST / $_GET（表单） requests.post("url", data={...})
json_decode(...) / 文档写”提交 JSON” requests.post("url", json={...})

为什么 data 行、json 不行？

PHP 的 $_POST 数组只认表单格式（application/x-www-form-urlencoded）。
传 JSON 时 Content-Type 是 application/json，PHP 不解析，$_POST 是空的，条件永远不成立。

小提醒

  • 判断依据永远是源码（服务端怎么读），不是响应头。
  • 拿不准就两个都试：先 data=，没反应换 json=。
